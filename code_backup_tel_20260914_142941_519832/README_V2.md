# クリニック営業マスター・完成版

既存コムデスクと厚生局の全施設一覧を統合し、HP・治療・集客施策を調べ、営業対象だけをコムデスクA〜AB列の28項目で出力します。入力・調査結果・手動修正は次回起動後も残ります。

2026-09-14更新：入力が少ない列数でも、Excel・CSVの1行目は毎回28項目で固定します。C列「名前」はクリニック名、AA列「院長名」は先生のお名前です。「クリニック名」「医院名」「名前」のいずれかを医院名として指定でき、その列だけでも取り込めます。入力にない項目は確認できた情報を補い、不明な項目は空欄です。元の28列に値や空欄がある場合はそのまま保持します。

```text
UUID	種別	名前	カナ	郵便番号	都道府県	住所１	住所２	住所カナ	Tel1	Tel2	Tel3	Tel4	FAX	URL	備考	旧社名	リードソース	履歴	記事名	休診日	診療日	午前始	午前終	午後始	午後終	院長名	開業日
```

まず **サンプルモード（APIキー不要）** をオンにしてください。架空4医院からHP確認済み3医院を抽出できます。サンプルと実データは別のデータファイルです。

## 初回セットアップ（Windows）

1. `clinic-list-filter-complete.zip` を右クリックし、**すべて展開**します。
2. 展開した `clinic-list-filter-complete` フォルダーを開きます。ZIPを開いたまま実行しないでください。
3. Python **3.12** を推奨します。Python未導入なら、Pythonをインストールしてから続けてください。
4. **setup_v2_windows.bat** をダブルクリックします。必要な部品のインストールが終わるまで待ちます。初回はネット接続が必要です。
5. 「セットアップが完了しました」と出たら、**start_v2_windows.bat** をダブルクリックします。
6. ブラウザーに「クリニック営業マスター」が表示されます。開かない場合は、黒い画面に出ている `http://127.0.0.1:8501/` 等のURLをブラウザーのアドレスバーに貼り付けます。

既存 `.venv` があればその環境を利用します。新規作成時は3.12を優先し、見つからない場合は導入済みの3.12以上を利用します。検証環境はPython 3.12です。3.11以下は使用しません。

旧版が8501で起動中なら、V2は8502などの空きポートを使用します。起動中は黒い画面を閉じないでください。終了はその画面で **Ctrl+C** です。

手作業で設定する場合は、エクスプローラーのアドレスバーに `powershell` と入力してEnterを押し、次を順番に実行します。Activateは不要です。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe scripts\launch_v2.py
```

`start_v2_windows.bat` は環境がなければ日本語の説明を表示します。初回の部品インストールは `setup_v2_windows.bat` が担当します。

## 2回目以降

**start_v2_windows.bat** をダブルクリックするだけです。同じフォルダーを使ってください。データを毎回取り込み直す必要はありません。

## 操作1：既存コムデスクを登録

1. 左側の **マスター管理** を開きます。
2. コムデスクのCSV・Excelをアップロードします。
3. Excelの場合はシートを選びます。
4. **UUID・案件ID／医院名／電話番号／都道府県／住所１・住所２／院長名／HP URL** などの列を確認します。UUID列が自動で見つからない場合は必ず選択します。
5. **既存案件を登録** を押します。

UUIDと元のセル値を保存します。厚生局の住所や電話が違っても、出力用の元行を勝手に書き換えません。先頭0・空白・改行・重複見出し・空の見出しも保持します。Excelの数式は値貼り付けしてから取り込んでください。

**28列（A〜AB）の形式に対応しています。**「名前」を医院名、「Tel1」を主電話として認識し、都道府県・住所１・住所２を照合用に結合します。Tel2〜Tel4・FAX・備考・履歴・院長名・開業日など、元の28列の値は出力時にもそのまま保持します。半角の「住所1・住所2」でも認識します。都道府県の列と住所内の都道府県が矛盾した場合は、取込を取り消して修正を案内します。

既存案件を入れる前に厚生局だけで試す場合も出力できます。見出し用テンプレートの事前取込は不要です。0件の場合も28項目の見出しを出力します。

同じファイルの再取込は重複登録しません。既存UUIDの別ファイルを再取込した場合、元行の先頭の登録を優先します。コムデスク側のデータを変更して再出力したい場合は、対象の元データと出力を確認してください。

複数の列構成を登録できます。出力は各行の元の列対応を使って28項目にそろえるため、異なる列数のリストが混在していても再取込は不要です。28項目以外の元の列は出力に追加せず、元データとしてDB内に保持します。

## 操作2：厚生局データを統合

**同梱の東京都マスターを取り込む** を押すと、2026-09-01基準の東京都医科一覧13,954施設を統合します。診療所・病院・休止施設を原データとして保持します。現存は公表一覧の基準日時点の状態です。歯科一覧は別途取り込んでください。

取込後は「統合」「新規追加」「要確認重複」の件数が表示されます。要確認の元レコードは別途保存され、確認が終わるまで独立した営業案件として出力しません。

更新時は、公式の**全一覧**をダウンロードし、「更新用の厚生局CSV・Excel」にアップロードします。

- 関東信越厚生局の同型帳票：**関東信越厚生局の帳票Excel** を選択。
- 標準CSV/Excel：**標準CSV/Excel** を選択。
- 医科・歯科を別の識別範囲として管理します。
- 医療機関番号 → 電話番号と医院情報 → 医院名＋住所の順に照合します。類似一致・共有電話・番号の競合は要確認に残します。
- 更新日、初回確認日、最終確認日を保持します。新しい更新では「前回の厚生局更新から追加された医院」で差分を表示できます。同じ更新日の再取込で差分を消しません。
- 一覧から見当たらなくなっただけでは閉院と判定しません。古い基準日のデータによる上書きは停止します。

標準列は `data/master/kouseikyoku_template.csv` を参照してください。診療科は `departments` または `診療科` 列で補完できます。全国47都道府県の標準形式を扱えますが、各地方厚生局の異なる帳票をすべて自動変換する機能ではありません。

## 操作3：Tavilyを設定して自動調査

1. **自動情報収集** を開きます。
2. **Tavily APIキー** にキーを入力します。キーは入力欄のセッションと実行中の処理だけに保持し、DB・ソース・ログへ保存しません。
3. **月間検索上限** を設定し、**月間上限を保存** を押します。初期値900回です。
4. **調査対象を絞る** で都道府県・診療科・新規医院などを選びます。調査側はHPが未発見の医院も対象です。
5. 「公式HP」「EPARK」「外部媒体」のいずれかを選びます。
6. 初回は **医院数10・検索上限10・最大HPページ数20** 程度で試し、**自動調査を開始** を押します。

環境変数でも設定できます。そのPowerShellから起動する場合だけ有効です。

```powershell
$env:TAVILY_API_KEY = "ここに自分のキー"
.\.venv\Scripts\python.exe scripts\launch_v2.py
```

検索はTavily basicに固定し、自動的に高消費のモードへ切り替えません。公式HPを見つけた後の内部ページは直接取得します。別の検索サービスは使いません。

### 無料枠と再開

- 月間上限と、調査ごとの検索上限の**両方**で停止します。
- 通常、同じ医院を再検索しません。検索結果はDBに保持します。
- **強制再調査** を選んだときだけ新しい検索を行います。同じ調査の中断再開にはキャッシュを利用します。
- EPARKはHPの有無と独立しています。電話を使った検索でURLが出ない場合だけ住所で補完するため、1医院に最大2検索を使います。
- 外部媒体は1回の検索結果から同時に分類します。媒体ごとに十数回検索しません。
- 上限到達後は、上限を調整して **続きから再開**。月間上限に到達した場合は翌月に再開できます。
- **一時停止** はページ取得の区切りで反映されます。ブラウザーを更新しても進捗は残ります。PC停止後も同じDBと調査履歴から再開できます。
- 失敗したAPIリクエストも1回として計上します。課金消費が確定しない通信障害でも、安全側で数えます。
- カウンターが把握するのは**このDB経由の検索**です。他のアプリ・別DBで使った分は控除欄に入力してください。Tavilyアカウント全体の無料残高を自動取得する機能ではありません。

[Tavily Search公式仕様](https://docs.tavily.com/documentation/api-reference/endpoint/search)に従い、`search_depth=basic`、`auto_parameters=false` を明示します。RESTアダプターを使い、暗黙の再試行によるカウント外のリクエストを避けています。

### 自動判定の意味

| 判定 | 確認方法 |
|---|---|
| HP確認済み | 医院名がページ見出しに一致し、電話番号または住所も一致。必要なら同じHPの概要・アクセスを補完 |
| HP未発見 | 今回の検索範囲で候補なし。不存在の証明ではない |
| 要確認・取得エラー | 本人確認不足、アクセス制限、DNS・SSL・タイムアウトなど。HPなしとは分離 |
| HPランク A/B/C/D | HTTPS、予約、スマホ設定、専門治療、院長情報、写真、料金等。年齢や開業年は別条件 |
| 治療カテゴリ | 見出しと本文、複数回の言及を確認。URL・キーワード・確度を保存 |
| 年齢 | 現在の院長を確認した医籍登録年、または公式HPの医学部卒業年から、仮定分布による59歳以下確率を計算 |

HPランクはHTMLで確認できる機能と内容の評価です。スクリーンショットによる美的評価ではありません。JavaScript実行が必要な内容、検索未収録のページ、取得拒否された内容は自動確認できない場合があります。

HPのお知らせ更新頻度はHPランクにも集客シグナルにも加点しません。**EPARKのHPリンク・予約・写真の有無から課金を判定しません。** 課金不明は不明のまま保存し、契約を確認できた場合に手動で補完します。Google広告も手動で確認済みにした場合だけ加点します。

YouTube・TikTokは公式HPからのチャンネル/アカウント導線等、AIチャットは埋込構造とサービス識別等、漫画・LP・専門サイトは専用コンテンツや本人確認を根拠にします。外部媒体は検索結果の医院名と電話/住所の裏付けを求めます。単なる掲載は実際の有料契約の証明ではありませんが、指定の営業ルールに従い掲載シグナルとして1点です。

**全シグナル1点。0個＝通常／1個＝集客投資シグナルあり／2個＝アツい／3個以上＝かなりアツい。** 同じ施策の重複は数えません。「アツい」は2個ちょうど、2個以上まとめて抽出する場合はシグナル数の下限を2にします。

## 操作4：営業対象を絞って出力

1. **営業対象フィルター** を開きます。
2. 必要な条件を選びます。標準では現存クリニック・HP確認済みのみです。
3. 例：医科／東京都／開業10年以内／59歳以下確率50%以上／HP A・B／内視鏡／集客投資シグナル2個以上。
4. 段階ごとの件数と最終対象件数を確認します。
5. 一覧で医院を選び、判定理由と根拠URLを確認します。
6. **この条件でExcel・CSVを作成** → **営業対象Excel** をダウンロードします。
7. 出力名は `final_comdesk_import.xlsx` です。

条件同士はAND。診療科や治療カテゴリの同じ項目内の複数選択はOR。必須のシグナルは選択したものすべてが必要です。

既存案件はUUIDと元の各項目の値を使用。新規医院は確認できた医院名・院長名・電話番号・住所等を28項目の対応する列に入力し、UUIDを空欄にします。C列「名前」はクリニック名、J列「Tel1」は電話番号、AA列「院長名」は先生のお名前です。HPは確認済みURLだけを補完します。指定年月日を実際の開業日として埋めることはありません。判定列を追加せず、入力にない項目のうち確認できないものは空欄です。元の28項目の値は空欄も含めて保持します。Excelの書式・他シートは複製しません。

開業10年以内は**指定年月日**が基準です。実開院日と必ず一致するわけではなく、**指定期間始**で若い医院と誤判定しません。院長59歳以下確率は年齢の事実ではありません。ちょうど50%を含み、根拠なし・矛盾は不明または要確認です。開設者が親世代で院長と違う医院も、DBから削除しません。

## 手動修正と要確認

医院詳細の **この医院の判定を手動で修正** を開き、項目・修正後の値・根拠メモを入力します。HP URL、HP状態・ランク、EPARK URL・契約、Google広告、治療カテゴリ、集客シグナルを変更できます。

自動値と手動値は別です。手動値が優先され、自動再調査で上書きしません。**この項目を自動値に戻す** で解除できます。確認日時・メモ・変更前後は変更履歴に残ります。

曖昧な重複は **要確認・設定** で確認します。候補へ統合するか、別医院として追加します。異なる既存UUIDを一方に上書きする統合は拒否します。

医籍情報は **マスター管理 → 医籍登録年を補完する** から既存テンプレートを取り込めます。同姓同名は既存の本人照合ルールを維持しています。公式医籍サイトのCAPTCHAを回避して自動検索する機能はありません。

## データとバックアップ

| 場所 | 内容 |
|---|---|
| `data/clinics.sqlite3` | 本番マスター、元のコムデスク行、根拠、手動値、調査履歴、検索回数 |
| `data/demo.sqlite3` | 架空サンプル専用 |
| `data/cache/doctor_license_cache.csv` | 医籍登録年の補完キャッシュ |
| `data/master/tokyo_current.csv` | 同梱の東京都標準マスター |
| `data/raw/` | 同梱の東京都公式Excel |

**要確認・設定 → バックアップを作成 → バックアップをダウンロード** で、使用中のDBの整合したコピーを保存できます。医籍補完キャッシュも使う場合は、アプリを終了後に `data/cache/doctor_license_cache.csv` もコピーしてください。APIキーはバックアップに入りません。

復元手順：

1. 黒い画面でCtrl+Cを押してアプリを終了します。
2. 現在の `data` フォルダーを別名でコピーして退避します。
3. `data` に既存の `clinics.sqlite3`、`clinics.sqlite3-wal`、`clinics.sqlite3-shm` があれば、3つまとめて別フォルダーへ移動します。
4. ダウンロードしたバックアップを **clinics.sqlite3** に名前変更し、`data` へ置きます。
5. 必要なら医籍キャッシュも戻し、アプリを起動します。

稼働中のDBを単独でコピーして復元することは避け、画面のバックアップ機能を使ってください。互換性のない既存DBは破壊せず停止します。同じV2形式の旧スキーマを更新するときは、更新前のバックアップを作ります。

## 困ったとき

| 表示・状況 | 対応 |
|---|---|
| Pythonが見つからない | Python 3.12をインストールしてセットアップを再実行 |
| 仮想環境がない・部品が不足 | setup_v2_windows.batを実行 |
| ブラウザーが開かない | 黒い画面の127.0.0.1のURLを貼り付ける。旧版とポートが違う場合あり |
| CSVの列数・文字コードエラー | CSVの引用符を修正、またはExcelをUTF-8 CSVで保存 |
| Excel数式エラー | 対象シートを値貼り付けして保存 |
| 要確認重複 | 医院名・電話・住所・医療機関番号を比較して手動確定 |
| HPが要確認・エラー | 詳細の候補と理由を確認し、HP URLと確認状態を手動補完、または強制再調査 |
| EPARKが不明 | 根拠不足やアクセス制限。URL・契約を手動補完 |
| 検索上限で停止 | 残数を確認。調査履歴から上限変更・再開。月間上限なら翌月に再開 |
| データファイルが使用中 | 別の取込処理が終わってから再操作 |
| フィルター結果が0件 | HP・年齢等の未確認が多い場合があるため、条件を一つずつ外して件数を確認 |

## 技術検証と範囲

`python -m pytest -q` で旧版とV2を検証します。テストではTavily実APIを使いません。架空HTML・検索結果で本人確認、誤検出防止、上限、中断再開、元形式出力を確認します。詳細は `docs/verification_v2.md`。

今回の実行環境はLinux / Python 3.12です。Windowsのバッチを用意していますが、Windows実機、実APIキーを使うTavily通信、実コムデスクへのインポートはこの環境から検証できません。自動判定の精度は実医院のページ内容と検索結果に依存します。

これは1台のPC向けのローカルアプリです。ログイン認証のないまま外部公開する設計ではありません。HP取得は公開IPに限定し、DNSを確認した接続先に固定します。移転先も検査し、robots.txt、ページ上限、HTMLサイズ、時間上限、アクセス間隔を適用します。取得拒否やCAPTCHAの回避は行いません。

## 設定ファイル

- `config/treatment_keywords.yml`：治療カテゴリとキーワード。
- `config/hp_ranking.yml`：HP機能・コンテンツの点数とランク境界。
- `config/age_model.yml`：既存の年齢仮定分布。

HP・治療の設定を変更した場合は、対象を強制再調査してください。年齢モデル変更や年越しは次の画面読込時に年齢確率を更新します。HP再調査前でも手動値は維持します。

旧版は `app.py` と従来のREADMEに残しています。完成版の起動先は **app_v2.py** です。V2の入口に関しては、このREADME_V2.mdを優先してください。
