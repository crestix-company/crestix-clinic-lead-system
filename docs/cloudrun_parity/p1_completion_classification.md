# P1完了判定の再分類（2026-10-20 続行依頼）

「PRがマージされている」「コードが存在する」を「実機で動作確認済み」「業務利用可能」と
同一視しないこと、という指摘を受けて、各項目を以下の4区分で再評価した。

- **①コード実装済み（静的確認のみ）**：ソースコード上は存在するが、本依頼のセッションでは実行・動作確認していない。
- **②実ブラウザ未検証**：コードは存在し、ロジック上は動くはずだが、実際のブラウザ操作では確認していない。
- **③画面のみ表示**：実ブラウザで表示されることは確認したが、操作（クリックして実際にデータが変わる等）までは確認していない、または意図的に操作不能。
- **④実操作可能（実機確認済み）**：実際にCanaryブラウザで操作し、期待通りの結果を確認した。

## P1総合判定

「ローカル版と同じ条件で、ローカル版と同じ医院集合がCloud Run READ ONLYからも見える」という
P1の中核要求は、**東京・大阪・北海道の3県について実機で異なる正しい値が得られることを確認**し、
かつSQL生成レベルの一致（`tests/test_cloudrun_parity_prefecture_search.py`、PR #127）で裏付けた。
ただし「ローカル版の同じ条件での結果と1件単位で突き合わせる」突合は、ローカルMacアプリを本セッション
内で起動していないため実施していない（ローカルMac側もSupabase Runtime DBに接続する構成であり、
理論上は同じ行を返すはずだが、未確認のまま「一致」と断定しない）。

## P2関連機能：コード存在 vs Cloud Runブラウザから実際に使えるか

| 機能 | コードは存在するか | Cloud Runブラウザから到達可能か | 区分 |
|---|---|---|---|
| Comdesk 1ファイル取込（`import_ui_comdesk_step`） | あり（ローカル専用） | **不可** - `simple_workflow_ui`はREAD ONLYで早期returnするため、Step1の取込UI自体に到達しない | ①コード実装済み・③画面にも出ない |
| Comdesk 2ファイル差分取込（`comdesk_snapshot_import.py`） | あり、既定OFF | **不可** - 同上に加え、`CLINIC_COMDESK_SNAPSHOT_DIFF_ENABLED`も未設定ならエラーメッセージのみ | ①コード実装済み・既定で無効 |
| Google Maps結果取込 | あり（ローカル専用） | **不可** - 同上、Step4のアップローダーに到達しない | ①コード実装済み・③画面にも出ない |
| HP・Email自動調査（単発/Cloud Runディスパッチ） | あり（`src/cloud_run/hp_executor.py`等、Phase C） | **不可（現行Canary構成では）** - `CLINIC_READ_ONLY_UI=true`の間はStep5のUIブロック自体がREAD ONLY早期returnより後にあるため到達しない。`CLINIC_HP_EXECUTOR=cloud_run`を使うには別途`CLINIC_READ_ONLY_UI=false`の書込み許可されたCloud Runデプロイが必要（今回未承認・未実施） | ①コード実装済み・現行Canaryでは到達不能 |
| 厚生局マスター取込 | あり（ローカル専用、`import_master`） | **不可** - 同上 | ①コード実装済み・③画面にも出ない |
| UUID紐付け（Comdesk再取込によるUUID付与） | あり（ローカル専用） | **不可** - Step7（`simple_comdesk_reimport`）はREAD ONLYでは到達不能 | ①コード実装済み・③画面にも出ない |
| Job制御専用DBロール分離・advisory lock・budget reserve | あり | 該当なし（Web READ ONLYから到達させない設計そのものが目的のため、「ブラウザから使えるか」という評価軸自体が当てはまらない） | ①コード実装済み（設計通り到達不能） |

**結論**：P2で要求されている書込み系機能は、現在のCloud Run READ ONLY Web構成（`CLINIC_READ_ONLY_UI=true`）
では、コードが存在していても**物理的にUIへ到達できない**よう正しく設計されている。「ブラウザから安全に使える」
状態にするには、(a) 書込み許可された別デプロイ（READ ONLY=false）を用意し、(b) 専用Writer/Job GCP SA・
最小権限DBロールを提供し、(c) 各機能ごとに今回文書化した二重ゲート（Feature Flag＋ロール）を外部から
実際に有効化する、という3つの承認が別途必要。今回のセッションではいずれも実施していない。
