# GAS・既存スプレッドシート連携 Phase 1（安全な骨格）

## 目的
Clinic Lead System のメール文章・下書きと、第一営業部_メール日程調整管理、および既存GASの案件・Gmail履歴を**二重登録せず紐づける**。

## 現在実装したもの
- 純粋関数による従来案件と Clinic UUID の保守的照合。
- 医院名＋電話または住所が一意一致し、院長名・メールなどに矛盾がなければ候補確定。医院名＋メールだけでは自動確定しない。
- UUID＋Campaign ID＋宛先＋記事あり/なしの操作キー生成。
- 既存GAS・スプレッドシート・Gmailの履歴照合が未完了なら登録禁止。
- 同一キーが既存履歴にあれば要確認にし、既存下書きを再利用する判断へ回す。
- 既存モジュール、UI、DB、GASに変更なし。

## 次の実装（未実装）
1. GASの submitForm と同等のケースID・トラッキング・候補日時・Gmail下書き関連処理をテスト環境で比較。
2. スプレッドシートの既存列を解析し、GAS登録の単一入口を追加。行の直接appendによる部分登録は禁止。
3. Gmail draft ID / thread ID / GAS case ID を同期し、失敗リトライ・部分成功の復旧を実装。
4. 既存シートを正として READ ONLY で Supabase の分析用サイドカーへ同期する（承認前の本番書き込みは禁止）。
5. 送信管理・反応分析の Streamlit UI を追加し、Feature Flag default OFF。
6. GASの計算結果と新集計の一致、HP・Email調査・既存UI性能の回帰検証。

## セキュリティと禁止事項
- 本番 Supabase migration / write、Gmail送信、GAS本番変更、既存ジョブ操作なし。
- 外部のAPIトークン、Google Chat Webhook、フォームアクセスキーをコードやログに記録しない。
- 初期移行で双方を自由に更新する双方向同期を行わない。
- 本番切替には運用担当者承認と再現テストの通過が必要。
