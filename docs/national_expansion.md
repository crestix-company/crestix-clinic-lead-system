# 47都道府県への拡張

## 共通部分

入出力、年齢分布、継承判定、営業対象判定、キャッシュは都道府県に依存しません。`config/settings.yml` の `prefectures` に県名・アダプター名・出典URL・マスタパスを追加すると対象県の選択肢を増やせます。

標準マスタの列は `data/master/kouseikyoku_template.csv` を共通契約とします。県ごとに取得・変換だけを差し替えます。

1. 各厚生局の現行「全一覧」を取得する。新規一覧だけを母集団にしない。
2. 対象県の標準マスタへ変換する。県名、医科/歯科、病院/診療所、基準日、出典を必須とする。
3. 廃止・休止・移転・組織変更の月次差分を別管理し、現行情報と突合する。
4. テスト用の実帳票を用意し、件数・区分・指定年月日・管理者・電話番号を照合する。
5. 変換に成功した県から選択肢を有効化する。

関東信越のExcel帳票パーサーは `src/enrichment/kouseikyoku_source.py` に分離済みです。東京都以外にも形状が同じファイルは使えますが、他県の実データ検証は未実施です。東京都の「公式更新」ボタンは東京都専用で、全国の自動取得を実装済みとはしていません。

## IDと誤結合防止

県名と医療機関番号を組み合わせてIDにします。全国化する際は、公式コード体系を確認して標準コードへ統一します。電話番号は複数施設・同一法人・移転先で共有される場合があるため、単独のユニークIDにはしません。

正規化した名称・住所の原文は必ず残します。同一ビル・同じ法人・同じ医師名だけを根拠に結合せず、複数候補は確認対象にします。移転や改称には旧名称・旧電話・有効期間を持つ別名テーブルを追加する方針です。

## データ量と運用

東京都MVPはpandasとメモリ内の電話・名称・住所インデックスです。全国・複数利用者で規模が増えたら、SQLite/PostgreSQLとジョブキューに移します。

- 医療機関：都道府県＋施設ID＋データ基準日。
- 医師：正規化氏名だけでなく、候補ID、医院との関係、本人確認証跡。
- 外部媒体：URL、確認日、確認者/出典、ラベル、HTMLハッシュ、ルールバージョン。
- 判定実行：入力ハッシュ、設定ハッシュ、使用マスタ版、実行日、出力行ID。

医籍登録年は氏名だけで一意になりません。永続キャッシュでは重複候補を保持し、確認済みの医院紐付けで解消します。

HTTP取得アダプターは提供元ごとに独立した上限・キャッシュ・停止条件を持たせます。公開APIや正式なデータ提供が利用可能になった場合に差し替えます。

## 現在の範囲

- 同梱データ：東京都、2026-09-01現在の公式医科一覧を変換済み。
- 動作：ローカルStreamlit、単一PCでの利用を想定。
- 未実施：全国の一括取得、実コムデスクリードへの接続/インポート、Web公開、医籍サイトの自動検索、EPARK課金専用HTML要素の実検証。
- 既存のコムデスク形式は列構成と元の値を保持することで対応します。コムデスク側の必須値や契約ごとの取込設定は、そのシステム側の条件にも依存します。
