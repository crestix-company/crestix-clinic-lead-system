## Explicitly not implemented (reported, not hidden)

1. **`import_maps_results` on the Supabase adapter** raises `NotImplementedError`. `google_maps.py:import_maps_results()`'s batch `find_target` scoring and the `PRESERVED_WEBSITE` anti-downgrade rule were only partially read while preparing this adapter (time-boxed); porting it without full line-by-line fidelity risked a silent business-logic divergence on a path that protects already-confirmed clinic websites from being overwritten by a weaker later Maps result. This needs a dedicated read-and-port pass with its own parity test before Gate2 can claim Google Maps import coverage.
2. **The actual UI/worker call sites are not rewired.** `app_v2.py`, `src/master/jobs.py`'s thread/lock orchestration (`run_job`/`_run_locked`/`_site_lanes`/`_research_one`), `src/enrichment/search_provider.py`, and `src/master/google_maps.py` still call `ClinicStore`/module functions directly, exactly as before. Only the job **state-transition primitives** (`create_job`, `claim_next_pending_item`, `mark_item_state`, `mark_job_status`, `pause_job`, `reset_job`, `job_limit`) were implemented at the Repository layer; the threading/lane-scheduling control flow around them was deliberately left untouched. **Rewiring these call sites is a live-runtime behavior change to the system that is the actual WRITE Primary today, independent of Supabase, and is deferred to the live cutover session with the owner present**, not attempted unattended. This is why "A+B direct SQLite runtime WRITE = 0" is **not** claimed below — see "Remaining direct SQLite WRITE paths."
3. **`ClinicStore._project()`/`._upsert()` in `src/master/store.py` are unmodified.** The identity-contract split exists as new, parallel code (`identity_contract.py` + the two write adapters); wiring the live `_project()`/`_upsert()` to use it is the same deferred live-runtime change as #2.
