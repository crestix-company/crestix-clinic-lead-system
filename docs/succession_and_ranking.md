# 継承候補と営業対象の判定

## 継承スコア

編集場所は `config/settings.yml` の `succession` です。

| 根拠 | 点数 |
|---|---:|
| 登録理由に継承・承継 | 50 |
| 登録理由に交代・管理者変更・開設者変更 | 25 |
| 開設者と管理者の姓が一致 | 10 |
| 管理者の59歳以下確率が閾値以上 | 10 |
| プロフィールに承継・二代目等 | 40 |
| プロフィールに父・母・親子等 | 20 |
| プロフィールに院長就任・副院長等 | 15 |
| 開設者の確認年齢と管理者推定中央値に20年以上の差 | 15 |
| 家族経営について手動の根拠記載あり | 5 |

合計は100点で上限、50点以上で候補です。ただし「継承/変更の登録理由」「プロフィールの承継記載」「親族記載と院長就任記載の組」のいずれかを必要とします。姓の一致と若手判定だけでは候補になりません。

「継承」と「交代」の点数は重ねません。プロフィールは肯定文のキーワードで判定し、明白な否定表現は除きます。文脈・親子関係・広告決裁権を確定する自然言語モデルではありません。

氏名に空白があるか、`owner_surname` / `manager_surname` が入力されたときだけ姓を比較します。「山田太郎」の先頭2文字を姓と推測する実装はありません。開設者が法人の場合、明示された「理事長」以降の個人名を比較できます。法人名だけから個人の一致を作りません。

「交代」は一律に親子継承とは扱いません。若手で交代記録がある場合、候補スコア未達でもパターン4として営業対象に残し、実務決裁権を要確認にします。

## 前提条件

自動採用の前に、対象都道府県・医科・診療所・現存を確認します。病院、歯科、休止・廃止等、対象県外は除外。未一致、区分不明、古い/未来のマスタ、入力電話番号なしは要確認です。

厚生局の現存は一覧基準日時点の登録状態です。リアルタイムの診療営業を保証する情報ではありません。マスタは初期値で62日以内のものを使い、古いものは自動採用を停止します。

## 採用とランクの順序

| 判定 | 条件 | 最終CSV |
|---|---|---|
| S | 若手、指定10年以内、継承候補、EPARK課金確認または他媒体あり | 含む |
| A | 若手、指定10年以内、開設者＝管理者 | 含む |
| B | 継承による採用条件を満たし、若手・10年以内・EPARK無課金またはHPが弱い | 含む |
| C・営業対象 | 若手＋継承候補、または若手＋EPARK課金確認。S/A/Bに未該当 | 含む |
| C・営業対象（要確認） | 継承/交代/管理者変更/開設者変更の記録と若手判定があるパターン4 | 含む、要確認にも出す |
| C・要確認 | 情報不足、採用条件未達、未一致、本人未特定など | 初期値では含めない |
| 除外 | 明確な対象区分外、または年齢基準未達＋継承候補なし＋指定10年超 | 含めない |

若手＝丸め前の59歳以下確率が50%以上。指定からちょうど10年は「10年以内」です。月日まで比較し、3650日への置換はしません。

ユーザー仕様ではBの記述に開設者・決裁条件がなく、最終採用の4パターンより広くなっています。そのため、このMVPは**まず採用4パターンを判定し、その中でランク付け**します。EPARK無課金やHPが弱いという情報だけで採用条件を追加しません。

年齢基準未達でも、開業10年以内または継承候補なら一律に除外せず要確認です。若手でも開業10年超・継承根拠なし・媒体投資不明なら同じく要確認です。

## 画面設定

通常院長型の期間・年齢・開設者管理者一致は、確認済みの条件に対して緩和できます。欠損値はチェックを外しても合格にはしません。「継承を含める」を外すとパターン2/4と継承経由のSを使わず、パターン1/3は引き続き判定します。「EPARKを使う」を外すとEPARKを根拠にしたS/パターン3を使いません。

「要確認の行も最終CSVに含める」をオンにすると、未一致を含む要確認行も元の形式のまま追加されます。除外行は追加されません。出力Excelの「判定条件」シートに条件を保存します。

## 4つのファイルの関係

判定付き全件は全入力行、除外ファイルは明確な除外行、要確認ファイルは確認事項のある行です。パターン4と、採用しつつ補足確認が残る行は、最終CSVと要確認リストの両方に出ます。したがって最終件数＋除外件数＋要確認件数は、必ずしも入力件数と一致しません。
