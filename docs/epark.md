# EPARK判定の確認結果と運用

2026-09-10に指定された次のページへの通常取得を試み、どちらもHTTP 403でした。実HTMLの差分は確認できていません。

| URL | ユーザーから提示されたラベル | 自動取得 |
|---|---|---|
| https://epark.jp/shopinfo/hpl15520/ | 課金済み | 403 |
| https://epark.jp/shopinfo/hpl202818/ | 無課金 | 403 |

この2件は、`data/cache/epark_cache.csv` にユーザー提示の確認情報として保存しています。取得して確認した契約情報とは区別し、理由と出典に「ユーザー提示」と記録しています。

## 初期動作

1. 有効期限内の確認済みマスタがあれば、そのラベルを使います。
2. 保存HTMLがあれば、予約/受付リンク数、画像数、本文文字数、JSON-LD件数を抽出します。
3. 検証済みの課金専用要素が設定されていれば、そのルールで推定します。
4. 根拠が足りなければ「不明」です。予約ボタンがないだけで無課金とは判定しません。

初期の `validated_rules` は空です。したがって新しい医院のHTMLだけから課金済み/無課金とは断定しません。課金マスタは `url, listing, status, reason, source, checked_at, verified` を使用し、`verified=true` と確認日を記録します。課金の有無は除外条件には使いません。

`listing` は「あり」「なし」「不明」です。EPARK URLがないことは「掲載なし」の証明にはならないため、初期値は不明です。

## 保存HTML

画面の「マスタを追加・差し替え」からHTMLをアップロードします。医院との対応は、HTMLのcanonical URL、または `hpl15520.html` のようなファイル名を使います。canonicalと医院URLが食い違えば採用しません。

`samples/html` は自作の架空テストHTMLです。実EPARKのHTMLを取得できたものではありません。予約リンクがある/ないだけでは課金を断定しないことを確認できます。

手元に課金済み・無課金の実HTMLがある場合：

```bash
python scripts/compare_epark_html.py --paid hpl15520.html --free hpl202818.html
```

構造の違いと特徴量をJSONで出します。2件の違いが有料専用要素とは限らないため、自動で設定を書き換えません。他の複数サンプル、出典、反例を確認した後、`config/settings.yml` の `epark.validated_rules` と `rules_version` を更新します。

## HTTPアダプターとキャッシュ

自動取得は画面でオンにした場合だけ実行します。許可先はEPARKの対象URLに限定、リダイレクトを追跡せず、プロキシ・CAPTCHA解答・偽装セッションなどを使いません。

初期上限は1回30リクエスト、間隔3秒、タイムアウト15秒、HTML 5MBです。403/401/429またはCAPTCHAを検出したら同じ実行の残りのHTTP取得を止めます。同じURLの繰り返し取得もキャッシュで防ぎます。

通常キャッシュ90日、403等は7日です。確認済みラベルの競合は不明になります。未検証の課金ラベルや、旧ルールによるラベルをそのまま引き継ぎません。取得したHTMLのSHA256と特徴量を記録し、HTML全文は通常キャッシュに保存しません。
